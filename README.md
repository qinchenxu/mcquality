# 装备品质

Minecraft NeoForge 1.21.1 模组。当前版本已经从“单一品质倍率”推进到“稀有度 + starter affix + 主动技能 + 粒子表现 + 详细属性面板”的第一版可玩闭环。

详细设计文档见 [docs/equipment-system-design.md](docs/equipment-system-design.md)。
当前功能完成情况见 [docs/feature-status.md](docs/feature-status.md)。

## 当前状态

当前已经实现的内容：

- 合成获得的护甲、武器、工具会自动生成品质
- 战利品表产出的护甲、武器、工具会自动生成品质
- 新装备会把 rarity、affixes、active_skill、passive_effects 写入物品数据组件
- 新装备会按武器、护甲、工具分池抽取 starter affix，并把结果物化到属性组件
- 旧版仅含 quality / active_skill / passive_effect 标签的装备仍可兼容读取
- 主手持有受支持武器时，可按 I 键打开装备详情面板
- 装备详情面板已接入真实的稀有度、词条实例、属性修正、主动技能和被动效果展示
- 高品质武器可以右键真实释放主动技能，并接入原版冷却
- 技能会触发自定义粒子，并通过原版粒子广播链路同步到客户端
- starter affix 与主动技能已经改成 JSON + reload listener 驱动

当前实现仍然是基础版：

- affix 池仍然是 starter 规模，尚未接入冲突组和更复杂的权重规则
- passive 目前仍主要用于结构化存储和展示，尚未形成完整结算闭环
- 当前多人环境和系统化平衡验证还未完成
- 详情面板已经可用，但 UI 仍在持续调整阶段

## 品质档位

| 档位 | 倍率 |
| --- | --- |
| 磨损 | -20% |
| 普通 | +10% |
| 罕见 | +30% |
| 稀有 | +50% |
| 史诗 | +80% |
| 传说 | +100% |

这些档位现在主要承担稀有度含义，决定 affix 数量范围和技能出现机会；旧版仅含 quality 标签的装备仍会按兼容路径读取。

## 当前规则

- 只对护甲、武器、工具一类装备生效
- 品质会在物品生成时写入，不会在普通查看时重复随机
- tooltip 目前只展示摘要信息，详细内容进入 I 键详情面板
- 新装备的强化结果主要来自 affix 实例，而不是统一倍率直接放大
- 主动技能优先走服务端右键判定，不依赖额外的 C2S 请求包
- 粒子同步当前走原版粒子广播链路，自定义网络消息留待更复杂状态同步时再补

## 已确认的开发方向

后续版本将按下面的方向继续迭代：

1. 扩 starter affix 池，并引入冲突组、完整权重和更丰富的词条层级。
2. 把 passive 从展示数据接到真实属性聚合或战斗事件中。
3. 扩展更多主动技能模板、更多触发方式和更成熟的技能表现。
4. 完成多人环境与平衡性专项验证。

## 计划中的系统设计

### 1. 稀有度与词条

后续会把当前单一品质拆成两层：

- 稀有度：决定词条数量、词条品质权重、技能词条出现概率
- 词条实例：决定具体加成数值、显示文本、技能信息和表现风格

这意味着未来装备不再只有“+50%”这样的单一结果，而是可能拥有多条不同类型的属性，例如：

- 攻击伤害提升 12.5%
- 攻击速度提升 4.0%
- 暴击或特殊机制类词条
- 主动技能词条或高级被动词条

### 2. 主动技能

第一阶段的主动技能方案：

- 技能主要挂在高品质装备上
- 由技能词条决定具体技能内容
- 先支持右键释放
- 技能需要服务端判定和冷却控制
- 客户端负责粒子和展示表现

适合作为第一批模板技能的方向：

- 范围斩击
- 护盾类技能
- 冲击或突进类技能

### 3. 技能粒子

技能粒子会作为表现层和技能本体绑定：

- 不同技能拥有匹配的视觉风格
- 粒子效果应与技能实际生效保持一致
- 多人环境下需要保证服务端判定与客户端表现同步

初期更适合按“技能风格”复用粒子，而不是为每个技能都做完全独立的资源。

### 4. I 键详细属性面板

计划中的详细属性面板用于承接完整装备信息，避免 tooltip 过长。面板打开条件为：主手持有受支持武器时按 I 键。

面板预计展示：

- 稀有度
- 词条列表
- 精确百分比和数值
- 主动技能说明
- 被动技能说明
- 触发方式
- 冷却时间
- 粒子或技能风格描述

tooltip 后续只保留摘要，详细信息全部进入独立面板。

## 运行

1. 安装 Java 21
2. 在工程目录执行 `gradle genIntellijRuns` 或 `gradle genEclipseRuns`
3. 执行 `gradle runClient`
4. 游戏目录可在 IDE 运行配置里改到 `/Volumes/KINGSTON/hmcl`

如果本机没有安装 Gradle，可以先安装后再生成 wrapper，或直接在 IDE 中导入 Gradle 工程。
